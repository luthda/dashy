# Component Patterns

Reference for shadcn/ui usage, layout, state management, toasts, and component conventions.

---

## shadcn/ui Primitives

All base UI primitives live in `components/ui/` and are generated by the shadcn CLI. **Do not
edit files in `components/ui/`** — customise via Tailwind classes at the call site or by
composing into domain components.

Common primitives used in Dashy:

```typescript
import { Button } from "@/components/ui/button"
import { Badge } from "@/components/ui/badge"
import { Card, CardContent, CardHeader, CardTitle } from "@/components/ui/card"
import { Dialog, DialogContent, DialogHeader, DialogTitle, DialogTrigger } from "@/components/ui/dialog"
import { Input } from "@/components/ui/input"
import { Select, SelectContent, SelectItem, SelectTrigger, SelectValue } from "@/components/ui/select"
import { Skeleton } from "@/components/ui/skeleton"
import { Table, TableBody, TableCell, TableHead, TableHeader, TableRow } from "@/components/ui/table"
```

## Component File Convention

One component per file. File name matches the component name in PascalCase.

```typescript
// components/logs/SearchBar.tsx
type SearchBarProps = {
  query: string
  onQueryChange: (query: string) => void
  onSearch: () => void
}

export function SearchBar({ query, onQueryChange, onSearch }: SearchBarProps) {
  return (
    <div className="flex gap-2">
      <Input
        value={query}
        onChange={(e) => onQueryChange(e.target.value)}
        onKeyDown={(e) => e.key === "Enter" && onSearch()}
        placeholder="Search logs..."
      />
      <Button onClick={onSearch}>Search</Button>
    </div>
  )
}
```

Rules:
- Props type defined above the component in the same file (not exported unless reused).
- Named exports only — no `export default`.
- Co-located private helpers are fine if tightly coupled to the component.

## Tag Chips

Tags render as shadcn `Badge` components in a flex-wrap row. Clicking a chip toggles it on/off.
Active tag IDs are tracked in the page component's local state and sent as `tagIds` in queries.

```typescript
// components/logs/TagChipRow.tsx
type TagChipRowProps = {
  tags: Tag[]
  activeTagIds: Set<string>
  onToggle: (tagId: string) => void
}

export function TagChipRow({ tags, activeTagIds, onToggle }: TagChipRowProps) {
  return (
    <div className="flex flex-wrap gap-1.5">
      {tags.map((tag) => (
        <Badge
          key={tag.id}
          variant={activeTagIds.has(tag.id) ? "default" : "outline"}
          className="cursor-pointer"
          style={{ backgroundColor: activeTagIds.has(tag.id) ? tag.color : undefined }}
          onClick={() => onToggle(tag.id)}
        >
          {tag.name}
        </Badge>
      ))}
    </div>
  )
}
```

## Layout — AppShell

`components/layout/AppShell.tsx` provides the sidebar and content area. All pages render inside
its `<Outlet/>`.

```typescript
// components/layout/AppShell.tsx
export function AppShell() {
  return (
    <div className="flex h-screen">
      <Sidebar />
      <main className="flex-1 overflow-auto p-6">
        <Outlet />
      </main>
    </div>
  )
}
```

Sidebar nav items: Logs, Metrics (shell), Traces (shell), Alerts, Settings.
Alert bell icon with badge count lives in the sidebar header — count comes from `useAlertStream`.

## State Management

### Server state — TanStack React Query

All data from the API is server state. Use domain hooks from `hooks/` (flat files — queries
and mutations combined per domain, e.g. `useSources`, `useTags`). See `data-fetching.md`.

### Local state — `useState`

UI-only state stays in `useState`. Examples:
- Active tag IDs on the Logs page
- Dialog open/closed
- Search bar input value before submission
- Time range picker selection

```typescript
const [activeTagIds, setActiveTagIds] = useState<Set<string>>(new Set())
const [isDialogOpen, setIsDialogOpen] = useState(false)
```

### When to lift state

If two sibling components need the same state, lift it to the nearest common parent. If that
parent is a page component, that's fine — pages are thin orchestrators and are expected to hold
state that coordinates their children.

## Toasts

Use shadcn's `useToast` hook exclusively. No other toast library.

```typescript
import { useToast } from "@/hooks/use-toast"

const { toast } = useToast()

toast({
  title: "Source created",
  description: "Connection test passed.",
})

toast({
  variant: "destructive",
  title: "Connection failed",
  description: error.message,
})
```

Alert firings trigger toasts from `useAlertStream`. Toasts auto-dismiss after 8 seconds.
Debounce: max 1 toast per alert per minute (tracked in the SSE hook).

## Empty States

Every list/table has an explicit empty state — never render a blank area.

```typescript
if (sources.length === 0) {
  return (
    <Card className="flex flex-col items-center justify-center p-12 text-center">
      <CardTitle>No sources connected</CardTitle>
      <p className="mt-2 text-sm text-muted-foreground">
        Connect a log source to start searching.
      </p>
      <Button className="mt-4" onClick={onAddSource}>
        Connect a source
      </Button>
    </Card>
  )
}
```

Standard empty states:
- No sources → "Connect a source" prompt (first-run experience)
- No log results → "No results — try widening the time range"
- No saved searches → "Save your first search"
- No alerts → "Create an alert"
- No alert firings → "No firings yet"

## Error States

Display inline error banners, not just toasts, for persistent errors (e.g. source unreachable).

```typescript
if (error) {
  return (
    <div className="rounded-md border border-destructive/50 bg-destructive/10 p-4">
      <p className="text-sm font-medium text-destructive">{error.message}</p>
    </div>
  )
}
```

## LOC Targets

| Type | Target |
|---|---|
| Page component | < 150 lines |
| Domain component | < 200 lines |
| Hook | < 80 lines |

If a component exceeds the target, extract sub-components into the same domain folder.

## Shared Components

Before creating a new UI widget, `grep` for similar patterns across the codebase. If the same
widget exists in another file, extract a shared component into `components/shared/`.

Examples of shared components:
- `ConfirmDialog` — reusable confirmation dialog for deletes
- `LoadingSpinner` — consistent loading indicator
- `StatusBadge` — alert status display (`ok`, `firing`, `error`)
